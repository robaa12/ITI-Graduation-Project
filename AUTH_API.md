# Authentication API

This document describes the authentication endpoints exposed by the backend.

## Base URL

Use the backend URL configured by `BETTER_AUTH_URL`.

```text
http://localhost:3000
```

All authentication endpoints use this prefix:

```text
/api/auth
```

The complete endpoint list is:

| Method | Endpoint | Purpose | Session required |
| --- | --- | --- | --- |
| `POST` | `/api/auth/sign-up/email` | Create an account with email and password | No |
| `POST` | `/api/auth/sign-in/email` | Sign in with email and password | No |
| `POST` | `/api/auth/sign-out` | End the current session | No, safe to call without one |
| `GET` | `/api/auth/session` | Get the current session | No |
| `POST` | `/api/auth/email-otp/send-verification-otp` | Send an email OTP | Usually no |
| `POST` | `/api/auth/email-otp/verify-email` | Verify a signup email with an OTP | No |
| `POST` | `/api/auth/sign-in/email-otp` | Sign in with an email OTP | No |

## Frontend Authentication Rules

The backend authenticates browser requests with an HTTP-only session cookie. The frontend must send cookies on every request.

```ts
const response = await fetch(`${API_BASE_URL}/api/auth/session`, {
  method: 'GET',
  credentials: 'include',
});

const data = await response.json();
```

For JSON requests, send:

```http
Content-Type: application/json
Accept: application/json
```

Do not read or store the session cookie in JavaScript. It is HTTP-only. The successful sign-in responses include a `token`, but normal browser clients should rely on the cookie and use `credentials: 'include'` instead of storing the token in local storage.

Cookie behavior:

- HTTP-only: yes
- Path: `/`
- SameSite: `lax`
- Secure: enabled in production
- Session lifetime: 7 days
- Session refresh/update age: 1 day

## Common Response Models

### User

```json
{
  "id": "usr_01JABC123",
  "name": "Jane Doe",
  "email": "jane@example.com",
  "emailVerified": true,
  "image": null,
  "createdAt": "2026-08-03T15:00:00.000Z",
  "updatedAt": "2026-08-03T15:05:00.000Z"
}
```

`image` can be a URL string or `null`.

### Session

```json
{
  "id": "ses_01JABC456",
  "userId": "usr_01JABC123",
  "token": "session-token",
  "expiresAt": "2026-08-10T15:05:00.000Z",
  "createdAt": "2026-08-03T15:05:00.000Z",
  "updatedAt": "2026-08-03T15:05:00.000Z",
  "ipAddress": "127.0.0.1",
  "userAgent": "Mozilla/5.0"
}
```

`ipAddress` and `userAgent` can be `null`.

### Better Auth Error

Errors generated by Better Auth normally have this shape:

```json
{
  "message": "Invalid email or password",
  "code": "INVALID_EMAIL_OR_PASSWORD"
}
```

The `code` is useful for frontend-specific messages. The backend may return other Better Auth codes depending on the failure.

Validation errors from the custom email/password validation have NestJS's shape:

```json
{
  "statusCode": 400,
  "message": "password must be at least 8 characters",
  "error": "Bad Request"
}
```

## Endpoints

### 1. Sign Up With Email

```http
POST /api/auth/sign-up/email
```

Creates a user account. Email verification is required, so a session is not normally created until the OTP is verified.

#### Request body

```json
{
  "name": "Jane Doe",
  "email": "jane@example.com",
  "password": "StrongPassword123",
  "image": "https://example.com/avatar.png",
  "callbackURL": "http://localhost:5173/dashboard",
  "rememberMe": true
}
```

| Field | Type | Required | Rules |
| --- | --- | --- | --- |
| `name` | `string` | Yes | Must not be empty |
| `email` | `string` | Yes | Must be a valid email address |
| `password` | `string` | Yes | 8 to 128 characters |
| `image` | `string` | No | Profile image URL or any string accepted by Better Auth |
| `callbackURL` | `string` | No | Optional callback URL |
| `rememberMe` | `boolean` | No | Optional session preference |

#### Success response

The route returns a `2xx` response. The controller is configured for `201`; the Better Auth handler may write `200` directly. The response payload is:

```json
{
  "token": null,
  "user": {
    "id": "usr_01JABC123",
    "name": "Jane Doe",
    "email": "jane@example.com",
    "emailVerified": false,
    "image": "https://example.com/avatar.png",
    "createdAt": "2026-08-03T15:00:00.000Z",
    "updatedAt": "2026-08-03T15:00:00.000Z"
  }
}
```

An email containing a verification OTP is sent automatically. The OTP expires after 5 minutes and allows 3 verification attempts.

#### Possible errors

| Status | Situation | Example code/message |
| --- | --- | --- |
| `400` | Invalid request body | `password must be at least 8 characters` |
| `400` | Invalid email or password | `INVALID_EMAIL` or `INVALID_PASSWORD` |
| `422` | Email is already registered | `USER_ALREADY_EXISTS_USE_ANOTHER_EMAIL` |

### 2. Sign In With Email And Password

```http
POST /api/auth/sign-in/email
```

#### Request body

```json
{
  "email": "jane@example.com",
  "password": "StrongPassword123",
  "callbackURL": "http://localhost:5173/dashboard",
  "rememberMe": true
}
```

| Field | Type | Required | Rules |
| --- | --- | --- | --- |
| `email` | `string` | Yes | Must be a valid email address |
| `password` | `string` | Yes | 8 to 128 characters |
| `callbackURL` | `string` | No | Optional callback URL |
| `rememberMe` | `boolean` | No | Optional session preference |

#### Success response

```json
{
  "redirect": false,
  "token": "session-token",
  "user": {
    "id": "usr_01JABC123",
    "name": "Jane Doe",
    "email": "jane@example.com",
    "emailVerified": true,
    "image": null,
    "createdAt": "2026-08-03T15:00:00.000Z",
    "updatedAt": "2026-08-03T15:05:00.000Z"
  }
}
```

The response also sets the HTTP-only session cookie. Use `credentials: 'include'`.

#### Possible errors

| Status | Situation | Example code/message |
| --- | --- | --- |
| `400` | Invalid request body | `email must be a valid email address` |
| `401` | Wrong email or password | `INVALID_EMAIL_OR_PASSWORD` |
| `403` | Email has not been verified | `EMAIL_NOT_VERIFIED` |

### 3. Sign Out

```http
POST /api/auth/sign-out
```

No request body is required. Send the current session cookie.

#### Success response

```json
{
  "success": true
}
```

The backend deletes the current server-side session and clears the session cookie.

### 4. Get Current Session

```http
GET /api/auth/session
```

This endpoint is safe to call when the user is logged out. It returns `null` instead of returning an error.

#### Optional query parameters

| Parameter | Type | Purpose |
| --- | --- | --- |
| `disableCookieCache` | `boolean` | Force a non-cookie-cache session read |
| `disableRefresh` | `boolean` | Prevent session refresh |

Example:

```http
GET /api/auth/session?disableCookieCache=true
```

#### Authenticated response

```json
{
  "session": {
    "id": "ses_01JABC456",
    "userId": "usr_01JABC123",
    "token": "session-token",
    "expiresAt": "2026-08-10T15:05:00.000Z",
    "createdAt": "2026-08-03T15:05:00.000Z",
    "updatedAt": "2026-08-03T15:05:00.000Z",
    "ipAddress": "127.0.0.1",
    "userAgent": "Mozilla/5.0"
  },
  "user": {
    "id": "usr_01JABC123",
    "name": "Jane Doe",
    "email": "jane@example.com",
    "emailVerified": true,
    "image": null,
    "createdAt": "2026-08-03T15:00:00.000Z",
    "updatedAt": "2026-08-03T15:05:00.000Z"
  }
}
```

#### Logged-out response

```json
null
```

### 5. Send Verification OTP

```http
POST /api/auth/email-otp/send-verification-otp
```

#### Request body

```json
{
  "email": "jane@example.com",
  "type": "email-verification"
}
```

| Field | Type | Required | Allowed values |
| --- | --- | --- | --- |
| `email` | `string` | Yes | Valid email address |
| `type` | `string` | Yes | `email-verification`, `sign-in`, or `forget-password` |

For the current frontend flows, use:

- `email-verification` after signup or when resending a signup verification code
- `sign-in` before OTP sign-in

The Better Auth plugin also defines `change-email`, but this route rejects that value and instructs callers to use a separate email-change endpoint. That endpoint is not exposed by this backend controller.

#### Success response

```json
{
  "success": true
}
```

The OTP is sent through the backend SMTP service. The OTP itself is never returned by this endpoint.

#### Possible errors

| Status | Situation | Example |
| --- | --- | --- |
| `400` | Invalid email or OTP type | `{ "message": "Invalid OTP type" }` |
| `429` | OTP rate limit reached | Rate-limit error from Better Auth |

### 6. Verify Email With OTP

```http
POST /api/auth/email-otp/verify-email
```

Verifies the email created during signup. This backend has `autoSignInAfterVerification` enabled, so successful verification creates a session and signs the user in automatically.

#### Request body

```json
{
  "email": "jane@example.com",
  "otp": "123456"
}
```

| Field | Type | Required |
| --- | --- | --- |
| `email` | `string` | Yes |
| `otp` | `string` | Yes |

#### Success response

```json
{
  "status": true,
  "token": "session-token",
  "user": {
    "id": "usr_01JABC123",
    "name": "Jane Doe",
    "email": "jane@example.com",
    "emailVerified": true,
    "image": null,
    "createdAt": "2026-08-03T15:00:00.000Z",
    "updatedAt": "2026-08-03T15:10:00.000Z"
  }
}
```

The response sets the HTTP-only session cookie. After this request, call `GET /api/auth/session` or navigate to the authenticated application.

#### Possible errors

| Status | Situation | Example code |
| --- | --- | --- |
| `400` | Invalid or expired OTP | `INVALID_OTP` or `OTP_EXPIRED` |
| `400` | User does not exist | `USER_NOT_FOUND` |
| `403` | More than 3 failed attempts | `TOO_MANY_ATTEMPTS` |

### 7. Sign In With Email OTP

```http
POST /api/auth/sign-in/email-otp
```

#### Request body

```json
{
  "email": "jane@example.com",
  "otp": "123456",
  "name": "Jane Doe",
  "image": "https://example.com/avatar.png"
}
```

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| `email` | `string` | Yes | Email that received the OTP |
| `otp` | `string` | Yes | OTP received by email |
| `name` | `string` | No | Used only if this email creates a new user |
| `image` | `string` | No | Used only if this email creates a new user |

#### Success response

```json
{
  "token": "session-token",
  "user": {
    "id": "usr_01JABC123",
    "name": "Jane Doe",
    "email": "jane@example.com",
    "emailVerified": true,
    "image": null,
    "createdAt": "2026-08-03T15:00:00.000Z",
    "updatedAt": "2026-08-03T15:12:00.000Z"
  }
}
```

This response sets the HTTP-only session cookie. If the email does not already belong to a user, Better Auth creates a verified user and uses `name` and `image` from the request.

#### Possible errors

| Status | Situation | Example code |
| --- | --- | --- |
| `400` | Invalid OTP | `INVALID_OTP` |
| `400` | Expired OTP | `OTP_EXPIRED` |
| `403` | More than 3 failed attempts | `TOO_MANY_ATTEMPTS` |

## Recommended Frontend Flow

### Password signup

1. Call `POST /api/auth/sign-up/email`.
2. Show the OTP verification screen.
3. Call `POST /api/auth/email-otp/verify-email` with the email and OTP.
4. Call `GET /api/auth/session` to load the authenticated user.

### Password sign-in

1. Call `POST /api/auth/sign-in/email`.
2. If the response is successful, load the user from the response or call `GET /api/auth/session`.
3. If the response is `403 EMAIL_NOT_VERIFIED`, send or resend an `email-verification` OTP and show the verification screen.

### OTP sign-in

1. Call `POST /api/auth/email-otp/send-verification-otp` with `{ "email": "...", "type": "sign-in" }`.
2. Show the OTP input screen.
3. Call `POST /api/auth/sign-in/email-otp` with the email and OTP.
4. Call `GET /api/auth/session` to load the authenticated user.

### Logout

Call `POST /api/auth/sign-out` with `credentials: 'include'`, then clear the frontend user state.

## Important Deployment Note

The backend enables credentialed CORS for `FRONTEND_URL`, which defaults to `http://localhost:5173`. If the frontend uses another origin, set `FRONTEND_URL` in the backend environment and restart the app. Cross-origin requests must use credentials for the session cookie to work.
